# PHASE 1 ~ 7

이 문서에는 프로젝트 개발을 7개의 Phase로 나누어 각 Phase의 목표와 완료 기준(체크리스트)을 정리합니다.

---

## Phase 1 — 초기 UI 노출

목표:
- 서버를 처음 실행했을 때 홈페이지 UI만 보여집니다. 디자인 확인용이며 어떤 기능도 동작하면 안 됩니다.

완료 기준 (체크리스트):
- 서버를 실행하면 루트 경로에서 홈페이지가 정상적으로 로드된다.
- 레이아웃(헤더, 푸터, 메인 섹션)이 디자인 시안과 일치한다.
- 네비게이션 바·섹션의 플레이스홀더 텍스트/아이콘이 보인다.
- 자바스크립트 기능(클릭, 폼 제출 등)은 비활성화되어 있다.
- 콘솔에 오류가 없어야 한다.

---

## Phase 2 — 네비게이션 및 홈 요약

목표:
- 상단 네비게이션 바에 `부산 게시판`, `지도`, `대시보드`, `축제 캘린더`, `북마크` 항목이 표시되고, 홈페이지에서도 각 항목에 대한 간단한 요약/프리뷰를 확인할 수 있다.

완료 기준 (체크리스트):
- 네비게이션 바에 5개 항목이 시각적으로 존재한다.
- 각 항목에 대한 카드 또는 요약 섹션이 홈 페이지에 포함되어 있다.
- 네비게이션 항목은 시각적 상태(hover, active placeholder)를 가짐 — 클릭 시 아직 기능이 없다는 피드백(비활성 토스트/툴팁 등)이 표시되어도 무방하다.
- 디자인/반응형이 유지된다.

---

## Phase 3 — `부산 게시판` CRUD (SPA)

목표:
- SPA 방식으로 `부산 게시판`이 동작하며 사용자가 게시글을 작성·조회·수정·삭제(CRUD)할 수 있다.

완료 기준 (체크리스트):
- 게시글 목록 페이지가 있고, 목록에서 글을 선택해 상세 조회가 가능하다.
- 글 작성 폼이 있으며 입력 유효성 검사가 동작한다.
- 작성 후 목록에 새 글이 반영된다.
- 글 수정 및 삭제 기능이 정상 동작한다.
- 서버 측 영속성(간단한 DB 또는 파일 저장)이 있어 재시작 후에도 데이터가 유지된다.
- SPA 라우팅(페이지 전체 새로고침 없이 뷰 전환)이 구현되어 있다.

---

## Phase 4 — `지도` (SPA)

목표:
- SPA 방식으로 `지도` 페이지가 동작하고, 부산 지도가 표시되며 카테고리별(음식점, 축제/공연/행사, 문화시설, 레포츠, 숙박, 쇼핑, 여행코스)로 항목을 필터링/토글하여 볼 수 있다.

완료 기준 (체크리스트):
- 지도가 정상 표시되고 초기 중심이 부산으로 설정된다.
- 각 카테고리 토글/버튼을 누르면 해당 유형의 POI(관광지)가 지도 상에 표시된다.
- POI 클릭 시 간단한 정보 팝업(이름, 간단 설명, 링크)이 나온다.
- 지도 레이어 전환은 SPA 내에서 동작하고, 불필요한 전체 페이지 리로드가 없음.
- 데이터는 적어도 샘플로 제공되어 시각적 검증이 가능하다.

---

## Phase 5 — `대시보드` (SPA)

목표:
- SPA 방식으로 `대시보드`를 클릭하면 부산 관광 데이터와 커뮤니티 현황 통계를 표와 차트로 확인할 수 있다. (데이터 시각화)

완료 기준 (체크리스트):
- 테이블 형태의 요약 데이터(예: 방문자 수, 인기 게시판 글 수 등)가 표시된다.
- 차트(막대/선/파이 등)로 주요 지표가 시각화되어 있다.
- 필터(기간 선택 등)로 데이터 범위를 조정할 수 있다.
- 데이터 소스(샘플 또는 실제 API)가 연결되어 최소한의 값이 표시된다.

---

## Phase 6 — `축제 캘린더` (SPA)

목표:
- SPA 방식으로 축제/행사 캘린더를 제공하며, 부산 권역의 축제/공연/행사 정보가 갱신일 기준으로 배치되어 조회 가능해야 한다.

완료 기준 (체크리스트):
- 달력 UI에서 월/주/일 보기로 이동 가능하다.
- 각 날짜에 등록된 축제/행사 목록이 표시된다.
- 이벤트 항목에 `갱신일` 정보가 포함되어 있고, 최신 갱신일 기준으로 정렬/표시할 수 있다.
- 배치(스케줄링) 로직이 있어 정기적으로(또는 수동 배치로) 데이터 갱신 시 갱신일이 업데이트된다. (간단한 스크립트나 배치 프로세스로 구현)

---

## Phase 7 — `북마크` (SPA)

목표:
- SPA 방식으로 `북마크` 페이지에서 사용자가 북마크한 게시글을 모아 볼 수 있어야 한다.

완료 기준 (체크리스트):
- 게시글 목록 또는 상세에서 북마크 추가/제거 버튼이 동작한다.
- 사용자가 북마크한 항목은 `북마크` 페이지에 목록으로 표시된다.
- 북마크 목록에서 항목을 클릭하면 해당 게시글의 상세로 이동한다.
- 사용자별 북마크가 유지되어야 하며(간단 세션/사용자 모델로 구현 가능), 재시작 후에도 보존된다.

---

## 공통 요구사항

- 모든 Phase는 접근성과 반응형 디자인을 고려한다.
- SPA 라우터를 사용하여 페이지 전환 시 전체 리로딩이 없어야 한다.
- 최소한의 테스트(수동 또는 자동)를 통해 각 Phase의 완료 기준을 검증한다.
